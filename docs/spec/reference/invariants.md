> **Les règles NON NÉGOCIABLES du framework Bonsai**

[← Retour à l'index](../README.md) · [ADR](../../adr/README.md) · [Anti-patterns](anti-patterns.md)

## Invariants I1–I58

Le titre historique est conservé pour les liens entrants ; cette table inclut également les extensions jusqu'à I99.

Les invariants sont les règles **NON NÉGOCIABLES** du framework.
Chaque invariant est numéroté, formulé sans ambiguïté et rattaché à un principe
opérationnel subordonné à la théorie. Une obligation contrôlable reçoit une garde
au plus tôt ; une obligation sémantique non vérifiable exige une justification et
une revue (§19 de la théorie). Une citation de test n’est pas une preuve générale.

Pour les quatorze contrats du lot 3, les énoncés ci-dessous reproduisent ceux du registre ; les précisions de nature, mode et état les suivent. **Nature** : C = conséquence, D = décision, E = énoncé ; **mode** : runtime (`run`), bootstrap (`boot`) ou typage (`type`). Les états distinguent strictement le livré, le livré partiel et le contrat cible non livré ; le registre YAML fait foi pour chacun (requalification du 4 novembre 2026, ci-dessous).
